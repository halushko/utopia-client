Проверено 15 ноября 2026 года. Исходный клиент: commit `7c34e3b`.
Исследованы все исходники, Dockerfile и workflows utopia-client, а также
связанные исходники доступных master-веток Kino Cat. Это не проверка версий,

## Что проверено на самом сайте

Авторизованная браузерная сессия, UNIT3D v9.2.0. Никакие торрент-файлы,
медиа или внешние аудиодорожки не скачивались; настройки аккаунта не менялись.
Cookies и токены не экспортировались. Go-сервис не запускался с настоящим NATS.

## API: известное и непроверенное

В footer сайта есть ссылка на официальную документацию UNIT3D:
https://github.com/HDInnovations/UNIT3D/wiki/Torrent-API-(UNIT3D-v8.x.x)

Прочитано актуальное определение Jackett:
https://github.com/Jackett/Jackett/blob/master/src/Jackett.Common/Definitions/utopia.yml

Оно использует GET `/api/torrents/filter`, Authorization Bearer, параметры
`seasonNumber`, `episodeNumber`, `tmdbId`, `tvdbId`, `imdbId`, `perPage`.
Результаты ожидаются в `data[].attributes`; `files[0].name` используется как
заголовок только для однофайлового релиза, также ожидаются `details_link` и
`download_link`. Опция Jackett, принудительно добавляющая UKR ко всем результатам,
не является доказательством наличия украинского аудио и для подписок непригодна.

Проверка API в браузере с обычной сессией и фильтром конкретной серии привела
на главную страницу, JSON не получен. Поэтому работа этих параметров именно
в API UTOPIA, схема ответа, пагинация и доступность MediaInfo **не подтверждены**.
Работа одноимённых HTML-фильтров не доказывает работу API-фильтров.
Bearer-запрос не выполнялся: API-ключ не запрашивался, не читался и не создавался.

Для сравнения прочитан upstream `app/Http/Resources/TorrentResource.php`
из HDInnovations/UNIT3D: он выдаёт `media_info`, `files` с name/size/index,
идентификаторы и ссылки. Это сведения о текущем upstream, а не о локальных
модификациях UTOPIA. Upstream download_link содержит персональный rsskey:
такие ссылки нельзя сохранять в fixtures, отчётах, логах или NATS-диагностике.

Рекомендация: после проверки авторизованного API использовать его для поиска,
деталей и файлов; HTML оставить адаптером для недостающей информации. Сейчас
восстановлен проверенный HTML-путь; неподтверждённый API не подключён в production.
При будущей настройке токен хранить только в серверном secret/env, не в чате
и не в Git. Ошибка API не должна запускать бесконечные попытки HTML-логина.

## Что было сломано и что изменено

* Заголовок произведения вместо релиза: теперь используется `torrent__name`.
* Файлы разбирались по чередованию непустых строк с пропуском первых трёх:
  теперь читается плоская таблица с полными относительными путями.
* Селектор основного языка отсутствует: добавлен актуальный `work__language-link`.
* MediaInfo по-прежнему читается из исходного текста, добавлены видеокодек,
  битрейт видео, HDR и исходные размеры. Поле resolution берётся из указанного
  трекером класса качества; при отсутствии остаётся прежний fallback по высоте.
  Этот fallback не является достаточным доказательством качества для подписки.
* Общие аудиометки вроде `768 kbps` ошибочно становились Studio. Теперь Studio
  извлекается только из явного разделённого `|` заголовка с MVO/DVO/VO/DUB/AVO.
  Незнакомый формат остаётся неизвестным. Это консервативная эвристика, не
  универсальный словарь студий и не основание для автоматической загрузки.
* `ParseSimilar()` был заглушкой. Теперь разбирает grouped rows, type с rowspan,
  размер, сидеров, дату и сезон/эпизод из родительских details.
  Отсутствующая Episode не означает автоматически проверенный полный сезон.
* Добавлен `GetSimilarPageByID(string)` для `category.TMDB`; старый int wrapper
  оставлен для совместимости. Нового NATS subject или Telegram-маршрута нет.
* Ошибочный ID больше не завершает процесс и не вызывает скачивание ID=0.
* Форматирование переживает nil MediaInfo и экранирует HTML в текстовых полях.
* HTTP получил timeout, синхронизацию инициализации и отказ при странице входа;
  ошибки инициализации возвращаются вызывающему коду. Тело ошибки логина не печатается.
* Файл публикуется в прежнем каталоге атомарным rename после записи. HTML/JSON
  не проходит предварительную проверку bencode-envelope. Это не полноценный
  валидатор структуры .torrent; такой разбор остаётся задачей torrent-клиента.
* Исправлен `%w` в Printf, из-за которого исходный `go test ./...` не проходил vet.

Fixtures сокращены из наблюдаемой структуры: заменены названия и ID,
удалены пользовательские блоки, Unique ID, формы и токены. Pack fixture содержит
три характерные строки из структуры десятифайлового пака, а не весь ответ сайта.
Тест grouped HTML — минимальный пример наблюдаемых классов, rowspan и details.

## NATS и связанные сервисы

| Компонент | Проверенная роль / ограничение |
| --- | --- |
| utopia-client | Слушает `UTOPIA_GET_TORRENT_INFO`, `UTOPIA_GET_TORRENT_FILE`; один аргумент ID |
| pinned kino-cat-core-go | Контракт команд `user_id` + `arguments`; ответ через `TELEGRAM_OUTPUT_TEXT_QUEUE` |
| kino-cat-bot-go master | Принимает Telegram text/document, публикует `chat_id`; выходной listener тоже ожидает `chat_id` |
| kino-cat-text-go master | Выбирает subject по префиксу, `_` в аргументах заменяет пробелами; `/utp_*` маршрутов в этой версии нет |
| kino-cat-torrent-go | Обрабатывает команды управления Transmission через core helper |
| kino-cat-file-go master | Main практически пуст; подтверждённого мостика UTOPIA → Transmission здесь нет |

Клиент теперь принимает оба входных имени ID; конфликт разных значений отклоняется.
Его выходной core-контракт не изменён. Несовместимость доступных master-версий
нельзя чинить обновлением только utopia-client: нужны версии реально развёрнутых
bot/text/file и настройка watched directory. Сообщение о сохранённом .torrent
не является подтверждением добавления задания или завершения загрузки.

Тесты используют локальный httptest и JSON, не настоящий брокер. Совместимость
исходных subjects сохранена; сквозная доставка через живой NATS не проверена.

## Проект строгих подписок — пока без загрузчика

### Профиль и нормализация

Для первой вручную выбранной серии сохранить неизменяемый снимок версии профиля:
category=TV, подтверждённые namespace-ID сериала, сезон и схема нумерации;
класс разрешения, source, platform, video codec, bit depth, HDR capabilities;
выбранные украинские дорожки (язык, студия, тип перевода, codec, channels/layout),
release group и значимый вариант edition/cut/PROPER/REPACK. Поля сохранять вместе
с источником, исходным значением и состоянием `known / unknown / conflicting`.
При нескольких украинских озвучках первая серия сама по себе не показывает,
какую пользователь выбрал: требуется выбор дорожки либо явная политика сохранения
всего набора. Default-флаг аудио не считать согласием пользователя.

Нормализация: Unicode NFC, регистр для сравнения, NBSP → пробел, разделители
точка/подчёркивание → пробел только в рабочей копии названия; исходные пути не
менять. До удаления разделителей разобрать S02E01, S02E01E02, S02E01-E03,
2x01 и полный сезон. Цифры в годе/разрешении не принимать за номер серии.
Исключать sample/trailer/extras из покрытия по явным правилам; непонятный
медиафайл требует проверки, а не автоматического исключения.

Словарь алиасов: AVC/H264/H.264 → H264; HEVC/H265/H.265 → HEVC;
WEB DL/WEB-DL → WEB-DL; BDRemux → source BluRay + remux=true.
WEBRip не равен WEB-DL; Encode не доказывает BluRay. Dolby Vision/HDR10/HDR10+
сохранять отдельными флагами, отсутствие слова HDR не доказывает SDR.
uk/ukr/Ukrainian → uk; названия студий объединять только по проверенному словарю,
никогда по нечёткому сходству. KyivstarTV, Megogo, 1+1 Production — разные значения.

Для каждого свойства сверять источники. Технические свойства брать из MediaInfo,
путь и покрытие — из списка файлов, идентичность — из ID, источник/группу/вариант —
из явных меток релиза. Это не повод молча игнорировать противоречие: несовместимые
утверждения переводят поле в conflicting. Пропущенное значение не совпадает с любым.
У обрезанного 4K не заменять класс 2160p фактической высотой 1600; оба значения
нужны отдельно. Битрейт сравнивать в нормальных единицах как диагностический
признак: он естественно меняется между сериями. Автоматическую терпимость нельзя
назначать без согласованной политики; точное равенство bitrate тоже непригодно.

### Сопоставление и причины

1. Найти кандидатов по подтверждённому ID и текущему сезону. Не полагаться на
   название и не смешивать TMDb movie/tv или TVDb/TMDb нумерацию без отображения.
   Помимо конкретной серии искать сезонные/многосерийные паки: episode-фильтр
   может их исключать. Обходить все страницы с ограничением нагрузки/backoff.
2. Получить подробности и полный список файлов. Построить множество `(season,
   episode)` из путей, сверить с метками раздачи. Файловый порядок не имеет значения.
   Непонятное покрытие не заменять предположением о числе серий.
3. Проверить жёсткие ограничения профиля. Другая украинская студия, source,
   codec, HDR, сезон, группа (если зафиксирована), edition или аудиоконфигурация
   дают `reject`. Неизвестное обязательное поле или конфликт дают `needs_review`.
4. MediaInfo одного файла не распространять на остальные файлы пака. При отсутствии
   доказательств однородности пака результат needs_review. Выбор файлов возможен
   только если downloader поддерживает селективное добавление до старта.
   Иначе пак с уже обработанными/непроверенными сериями автоматически не запускать.
5. Только после прохождения всех жёстких ограничений ранжировать эквивалентные
   релизы по наличию сидеров и стабильным tie-breakers. Высокий score никогда
   не компенсирует несовпадение студии. Если кандидата нет — оставить серию pending.

Результат кандидата: verdict, версия правил/профиля, список reason codes и
свидетельств: например `audio.studio.mismatch: KyivstarTV != Megogo`,
`video.hdr.unknown`, `coverage.missing_next_episode`, `season.mismatch`,
`pack.media_unverified`, `episode.already_processed`. Пустая выдача не rejection
самой подписки. Сначала Telegram должен показывать решения без скачивания.

### Хранение и устойчивость

Не хранить подписки только в памяти. Достаточна SQLite на постоянном volume:
subscriptions/profile_versions, episodes, candidate_decisions, download_jobs,
outbox. Уникальные ключи: `(subscription_id, season, episode)` и `(tracker,
torrent_id, content_revision/infohash)`; обновляющийся сезонный торрент может
иметь тот же ID и новое содержимое. Для пака хранить выбранные файлы и покрытие.

`next_episode` — первая необработанная серия текущего сезона, не максимальный
найденный номер +1. E03 не закрывает отсутствующую E02. Переход сезона требует
явного действия, а нулевые/specials не смешиваются с обычной нумерацией.
В одной транзакции резервировать серии и создавать outbox-задание. Состояния:
pending → reserved → submitted → acknowledged/completed; uncertain требует
сверки с Transmission по infohash и выбранным файлам, а не слепой повторной отправки.

Core NATS сам по себе не обеспечивает надёжное задание и exactly-once. Для
гарантий нужны durable delivery (например JetStream/outbox), idempotency key
у downloader и подтверждение с infohash. После crash между добавлением в
Transmission и записью acknowledgment сверять реальное задание. Lease/unique
constraint защищает от двух параллельных проверок. Завершённые эпизоды не
скачивать заново; обновление pack metadata не сбрасывает их состояние.

### Минимальные изменения архитектуры и запуск

Оставить navigator → parser/entities → listeners и существующий downloader.
Добавить адаптер API только после проверки ответа. Отдельный package subscriptions
отвечает за нормализацию/решения, storage — за SQLite и outbox, worker — за polling.
Новый publisher не вызывает существующий download listener до прохождения этапов:
offline tests → dry-run на реальных метаданных → ручная проверка причин → явное
включение. Нужны тесты на каждую жёсткую характеристику, неизвестность/конфликт,
другую озвучку, пропуск серии, specials, mixed-season pack, обновление пака,
рестарт, два worker и crash вокруг downloader acknowledgment.

В этой ветке нет worker, базы подписок, новых Telegram-команд или автоматического
скачивания. Представлен проверенный ремонт парсера и конкретный проект следующего
этапа; отсутствие bearer-проверки и end-to-end downloader-контракта не скрывается.
